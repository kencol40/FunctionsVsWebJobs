##Story
As a Software engineer I want to explore the differences, pro's and cons for development and maintenance for two approaches to performing the same tasks using Microsoft Azure tooling. In this case I specifically want to explore Azure Functions vs Azure webjobs.

##Context
I have 2 tasks to perform 
	1) When a CSV file is uploaded to a configured blob storage container, I want to run a process that will read the CSV file, write the data to an SQL database using entity framework.
	2) When a message is uploaded into an Azure service bus queue, I want to run a process that consumes the message and writes the body of the message to an SQL database using entity framework.

I want to showcase the tasks being executed using 2 different approaches.
	1) A standard azure function app with bindings for blob to consume the file and service bus triggers to consume the message when they arrives.
	2) use a webjob to consume the file and message. I'm not sure of the webjob features to enable consuming the file and message so I want you to find something that will do this.

The reason I'm doing this is or organisation have been having discussions on this topic with statements being made that functions are rubbish and generate additional long term maintenance costs. Coupled with the fact that Functions are simply built on top of webjobs anyway.  So my purpose is to explore the discussion with actual code and get a comparison and discussion on what works well and what does not and how much additional code do I need anyway.
